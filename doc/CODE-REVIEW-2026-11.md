# xaea code review and development priorities

Reviewed main at `e2d4172`, November 23, 2026. xaea is a command-line application, built with Rust 2024 and a declared minimum Rust version of 1.88. The review covers all 22 production Rust source files, the integration suites, and the supporting fixture, benchmarking, verification, and release paths.

**Keep the extraction pipeline. Fix ownership of temporary files first, make the signature tests exercise the intended bytes, then put a measurable bound on decoded memory.** The most promising user-facing addition is a file listing. It fits a boundary the code already has and would be a good first Rust feature for a maintainer learning the language.

## How to read the code

An AEA is the outer container. It describes the compressed segments and carries the information needed to authenticate them. Inside those segments is one continuous Apple Archive (AA01) stream describing directories, files, links, and file contents. A segment boundary can fall in the middle of a file or even a record header. That distinction explains why decoding can be parallel while parsing has to preserve order.

1. **Start at the command line.** `main.rs` dispatches three commands. `cli.rs` declares flags once, and `completions.rs` generates shell completions from the same declaration. `cmd.rs` opens a memory-mapped view of the input. `spool.rs` makes standard input seekable by first copying it to a temporary file. `exit.rs` translates errors into the exit codes scripts depend on. In Rust, a `Result` carries success or an error, and `?` returns the error immediately. That convenience matters in the worker-cleanup finding below. [Entry point](../src/main.rs) · [Exit-code contract](ERROR-CODES.md)
2. **Follow one segment.** `envelope.rs` validates the segment layout, including the end of the file and total decoded size. `kdf.rs` derives the keys for the root, clusters and segments. `sigverify.rs` checks the content signature and certificate chain. `cmd/inspect.rs` can stop after describing the envelope or run the checks. Signature, keyed integrity checks (MACs), decoded checksums and trust in the signer answer different questions. [Envelope](../src/envelope.rs) · [Format notes](FORMAT-NOTES.md)
3. **Follow one file.** `cmd/extract.rs` selects settings. `extract.rs` starts decoder and writer threads. `extract/decode.rs` reads each segment at a known file offset and uses `xz.rs` for compressed segments. The coordinator restores stream order. `aa.rs` keeps partial headers between calls and sends file data to a `Sink`, a Rust interface with just two operations, receiving a record and receiving a piece of file data. A piece shares ownership of the decoded allocation through `Arc`. Passing it to a writer avoids copying its bytes and keeps the *whole segment* alive until the last owner releases it. [Parser](../src/aa.rs) · [Coordinator](../src/extract.rs)
4. **Follow the write.** `extract/sink.rs` checks each record and routes a file and all its pieces to one writer, preserving order for that file. `extract/paths.rs` applies the path policy. `extract/writer.rs` creates and fills files, while `decmpfs.rs` can store them with transparent macOS compression. After the writers drain, `extract/links.rs` creates deferred symlinks and the writer applies directory permissions. `extract/status.rs` serves progress requests and `prof.rs` supplies optional timing counters. Those counters sum work across threads, so ten seconds of writer time need not add ten seconds to elapsed time. [Writer](../src/extract/writer.rs) · [Performance history](PERFORMANCE-NOTES.md)

## Correctness findings, in priority order

### 1. Clean up only files the operation owns

**High · data loss · small fix.** The macOS compression probe opens its temporary path with `create_new(true)`, which correctly refuses a collision. The outer cleanup then calls `remove_file` even when that open failed. A pre-existing entry at the probe name can therefore disappear simply because someone extracted into that directory. Compression probing is enabled by default on macOS and happens before signature verification. Use a `tempfile::NamedTempFile` created in the destination and have its owner perform cleanup. Keep both compression layouts and the read-back check. Verify that an unsuccessful creation preserves an existing sentinel. This is the ownership rule behind Rust's RAII pattern, where cleanup belongs to a successfully acquired resource. [Probe, lines 414–441](../src/decmpfs.rs#L414) · [Call site](../src/cmd/extract.rs#L45)

The benchmark tools have a related hazard. The Python harness documents that its output directory is disposable, but even the advertised read-only dry run schedules recursive removal before measurement and again at exit. The standalone filesystem microbenchmark also removes its caller-supplied root. Let the caller choose a **parent volume**, allocate a unique scratch child there, and delete only that child. A dry run needs no tree cleanup. Check an existing sibling and parent sentinel after success and failure. This matters before asking contributors to collect performance data. [Benchmark harness, lines 149–190](../scripts/bench.py#L149) · [Filesystem microbenchmark](../scripts/fs_create_bench.rs#L9)

### 2. Repair the signature and root-MAC tests before extending them

**High · false confidence in verification · small fix.** Both integration suites derive the signature offset from the length of the first authentication *value*. The format puts the signature after the *entire encoded authentication section*, including the length prefix, key, terminator, and every value. On the current synthetic fixture the omitted overhead is 46 bytes. Both hand-calculated mutation positions are early. Changing other authenticated bytes can still produce the expected failure code. This is why a green test does not establish that its named check ran. [Exit-code helper](../tests/exit_codes.rs#L41) · [End-to-end test](../tests/e2e.rs#L286) · [Builder layout](../scripts/make_test_aea.py#L227)

Read the four-byte little-endian authentication length at header bytes 8–11. Share that one helper across both tests. For a signature-only mutation, require a parseable JSON report, a failed content signature, and intact header MACs. Assert the complementary result for a root-MAC change where the format permits it. In CI, install and explicitly check Python's `cryptography` package with the same isolated interpreter the tests use. The helper currently returns early when the dependency is absent, and the test runner counts those returns as passes. This gives issue #49 a specific acceptance test. [Test dependency check](../tests/common/mod.rs#L40) · [CI test job](../.github/workflows/ci.yml#L50)

### 3. Enforce filesystem boundaries at the operation that changes the tree

**High · containment · platform-specific validation needed.** The link pass reasons about ancestor paths by lowercasing Rust strings. The filesystem resolves actual names, which can also be equivalent under Unicode normalization. A string-level independence check cannot establish that two names identify different entries on every supported volume. Also, deferred directory permissions are applied through full paths after links exist. Make the destination directory handle the authority for traversal, refuse symlink parents during mutation, and apply directory modes through verified directory handles. Apply restrictive child modes before restrictive parent modes so a legitimate parent permission cannot block completion. Keep the existing fast path only where it preserves those guarantees. Validate ordinary Unicode names and permission restoration against the target filesystems; include both case-sensitive and default macOS volumes. This is a source-level concern, with no platform reproduction performed in this review. [Link independence](../src/extract/links.rs#L32) · [Final ordering](../src/extract/sink.rs#L95) · [Directory chmod](../src/extract/writer.rs#L225)

### 4. Join workers on every exit and preserve the cause of failure

**Medium · diagnostics and partial output · moderate fix.** The final flush deliberately joins writers and reports their filesystem errors first. Earlier calls to receive, feed the parser, and finish the stream use `?` before reaching those joins. If a writer has already failed, the parser may report only that its channel closed. Dropping a Rust thread handle detaches the thread. Other workers can still be draining queues as the CLI returns. Keep the stream result, close the channels to unblock producers and consumers, join all workers, then select the original cause. On cancellation, define whether queued writes drain or stop. Add a controlled writer-error test requiring the original path and error and a stable output tree after the pipeline returns. Keep exit code 6. [Early exits and joins](../src/extract.rs#L353) · [Channel error](../src/extract/sink.rs#L157)

### 5. Use the complete public-key encoding for RSA issuers

**Medium · supported chain compatibility · small fix.** The certificate reader stores the *contents* of the SubjectPublicKeyInfo sequence as `spki_der`. The RSA verifier later asks a DER decoder to read a complete SubjectPublicKeyInfo object, including its outer tag and length. The EC path takes a different route, so the passing Xcode fixture does not cover this mismatch. Store the complete sequence, for example `spki_der: cert.public_key().raw.to_vec()` with the locked parser. Add a valid P-256 content signer with an RSA issuer and check the individual chain result. A second maintenance step is to reduce the duplicate DER walking where the existing X.509 parser already exposes the signed bytes. [SPKI extraction](../src/sigverify.rs#L268) · [RSA verifier](../src/sigverify.rs#L387)

### 6. Make format support and verification outcomes explicit

**Medium · CLI accuracy · small independent fixes.** Extraction chooses stored versus compressed data from the segment lengths and sends every compressed segment to the XZ decoder. Inspection's checksum path checks for LZMA up front, even for an entirely stored archive. Define the supported combination once and apply it in both commands before starting work. Cover stored-only input and a recognized, unsupported codec. Similarly, envelope parsing rejects encrypted profiles before the extract-specific branch that describes them as inspect-only. Either expose header-only inspection for those profiles or describe the actual restriction consistently. [Decode dispatch](../src/extract/decode.rs#L56) · [Inspection checks](../src/envelope.rs#L541) · [Profile gate](../src/envelope.rs#L222)

The text summary prints “verified” for every dry run, including `--dry-run --no-verify`. JSON already distinguishes the two. Use “decoded” for the unchecked case. Reject zero thread counts at argument parsing, or report the effective counts after clamping. Today the JSON can report zero writers while the pipeline uses one. Test the public command with these combinations. [Summary and options](../src/cmd/extract.rs#L61) · [Effective counts](../src/extract.rs#L291)

## Performance investigations worth running

**First, bound how far decoding can get ahead.** The channel capacity bounds messages waiting *in the channel*. The coordinator keeps receiving later segments into a separate `pending` map while it waits for the next required index. One slow early segment can therefore retain buffers well beyond `--readahead`. A writer holding even a tiny piece can also keep an entire decoded segment alive. The current RAM-based default is a tuning heuristic, not a process memory ceiling. This is a structural observation. The additional peak on real archives has yet to be measured. [Decoder scheduling and reorder map](../src/extract.rs#L313) · [Shared piece](../src/aa.rs#L24)

Start with a deterministic scheduling test that delays the next required segment and counts how many later segments can start. Prototype a sliding window on **issuing segment indices** and release slots as the parser advances. Simply stopping receives when the map fills can deadlock the decoder holding the missing segment. Record maximum pending bytes, unique live decoded bytes and peak resident memory (RSS). Extend issue #47's writer-queue experiment only after this measurement. Writer messages, queued file bytes, and unique pinned segment bytes are three different quantities.

**Second, bound single allocations as well as queue depth.** The liblzma call supplies an unlimited decoder memory allowance. The declared output segment size can itself be large. On the output side each compressed writer builds an in-memory resource fork for one file. Its chunk offsets are cast to 32 bits before the final size check, and the spill-to-plain path reads those offsets. Set a supported per-decoder memory allowance using fixture evidence, validate sizes before allocation, and choose plain storage before a chunk table or offset exceeds its representation or working budget. Test offset arithmetic with a small injected limit, so CI can exercise the transition without allocating gigabytes. Read the resulting file back and compare bytes and modes. [Decoder allowance](../src/xz.rs#L98) · [Chunk table](../src/decmpfs.rs#L237) · [Offset write and spill](../src/decmpfs.rs#L293)

**Third, measure full extraction on the machines that would benefit.** At revision `931933a`, the project recorded **12.30 s compressed, 8.23 s plain, 4.90 s dry-run** on an M3 Max with the Xcode 27.3 beta 2 archive. Compressed output took about 3.9 GiB on disk. Those are historical measurements. PR performance CI gates verified dry-run time, which cannot detect a writer-only regression. Use the existing opt-in full-extract job for changes to writers or compression. Pair baseline and candidate runs on an otherwise idle machine, rotate run order, and report wall time, peak RSS, disk usage and output fidelity. Cover a lower-memory Mac as well as the existing high-memory baseline. A memory improvement is a win if it reduces peak RSS on that workload while keeping elapsed-time changes within a predeclared tolerance. [Measured baseline](PERFORMANCE-NOTES.md#baseline-numbers) · [Full-extract job](../.github/workflows/perf.yml#L114)

**Leave directory affinity, a separate encoding pool, and decoder-default changes low on the list.** Directory affinity reduced some filesystem time yet made total extraction slower or indistinguishable in the measured trials. The shared encoding pool and alternative decoder already have end-to-end investigations. The final symlink pass is already parallel for independent lists despite an older “not yet tried” paragraph. Reopen those experiments when a new workload or profile shows a different bottleneck. [Directory-affinity results](PERFORMANCE-NOTES.md#directory-affinity-measured-46-the-contention-is-real-the-savings-are-not-on-the-wall) · [Implemented link pass](../src/extract/links.rs#L55)

## Feature roadmap

1. **List the payload.** Add a read-only sink that emits one row per record with path, type, size, mode, and link target. Stream a machine-readable form such as JSON Lines so callers can search a large archive without building an in-memory manifest. Specify whether listing verifies the whole archive and what a nonzero exit means after partial output. The first implementation still decodes every segment to find record boundaries. Acceptance criterion: list output matches the synthetic fixture manifest and succeeds regardless of entries in the current directory. This is the smallest feature that teaches the command, parser, and test architecture together. [Sink interface](../src/aa.rs#L54)
2. **Extract a selected subtree.** Reuse the same parser and segment verification. Filter at record dispatch, consume skipped blobs, and send only selected files and required parent directories to writers. This can save output space and filesystem work. It will still pay the archive scan and decode cost without a separate index. Define how relative symlinks to omitted entries behave. Compare the selected tree with the corresponding subtree of a full extraction. [Dispatch sink](../src/extract/sink.rs#L166)
3. **Expose signer trust as a policy choice.** Private or re-signed archives can pass the current integrity checks. Inspection reports Apple root trust separately and extraction warns about an untrusted root. Add an opt-in requirement for a documented signing policy and surface the result in extraction JSON. Before calling a result “Apple distribution”, specify the acceptable leaf purpose, issuer constraints and root policy. Merely checking the final root bytes does not establish distribution authorization. Cover private-CA and real Xcode cases and preserve the existing default. [Trust calculation](../src/sigverify.rs#L431) · [Extraction policy](../src/extract.rs#L205)
4. **Make failed extractions easier to recover from.** An archive can fail after files have been written, for example on a later checksum or top-level collision. A retry then encounters those entries. For the common single-app case, consider an optional staging directory on the destination volume, followed by a no-overwrite publish after verification and final metadata work. Define multiple-top-level semantics separately, since a series of renames cannot publish a group atomically. Test failure, interruption, existing destinations and success. [Collision policy](../src/extract/sink.rs#L139) · [Final verification barrier](../src/extract.rs#L367)

## What to preserve and how to verify future work

- The parser's chunk-boundary tests, the cross-language KDF vectors, and synthetic tree comparison test behavior at the interfaces most likely to break during optimization. Maintain them alongside the real fixture. [Parser tests](../src/aa.rs#L306) · [Key vectors](../src/kdf.rs#L92) · [Tree fidelity](../tests/e2e.rs#L145)
- The full-tree comparison script needs typed records before serving as a fidelity gate. It hashes regular-file contents and link-target strings in the same namespace, omits directories and permissions, and uses shared filenames in the temporary directory. Include entry type, mode, path and content hash or literal link target as appropriate. Use private temporary storage per invocation. Compare a fixture pair that differs only in an executable bit, an empty directory, or an entry type. Coordinate with PR #53 before duplicating this work. [Tree comparison](../scripts/verify.sh#L8)
- Keep the original archive file handle with its mapping and pass it to positional reads. Extraction currently reopens the input pathname, so renaming or replacing a download between open operations can produce a spurious failure or mix input identities in unchecked mode. Holding one handle also simplifies stdin spool ownership. In-place modification of a mapped file remains a separate input assumption. [Mapped input](../src/cmd.rs#L23) · [Second open](../src/extract.rs#L285)
- Keep profiling compiled out of normal builds. Exercise the profile feature in CI and add a minimum-version compile check if Rust 1.88 is a compatibility promise. The current workflow checks a pinned newer compiler. Keep the release signing, packaging, and platform jobs separate from extraction timing. [Profiling](../src/prof.rs) · [CI compiler and jobs](../.github/workflows/ci.yml#L12)

**Local verification.** On macOS with Rust 1.100.0, formatting and locked Clippy passed. The normal suite reported 50 passes and two ignored tests. The all-features suite also passed, with no skip notices in its uncaptured output, and all-features Clippy passed with warnings denied. I separately ran the ignored release-mode verification against the local 2 GiB Xcode 27.3 beta 2 AEA. It passed the checks for 624 segments, three clusters, the recorded original size, signature, checksums and Apple root trust. The real-fixture command verifies the archive without constructing an output tree. No new comparative benchmark, Linux run, release signing, or full Xcode tree comparison was performed. The performance proposals above are experiments, and the findings are based on reading the implementation except where a check is explicitly reported.
